# Commit messages and branch names (Agent3D)

The history uses a short **scope prefix** followed by what changed, sometimes
with a Conventional Commits type (`fix(assets): …`, `docs(readme): …`):

```
<scope>: <subject>
<type>(<scope>): <subject>

<body — optional: why, and what a reviewer must know>
```

Examples from `git log`:

```
render: AGENT3D_CDP_TIMEOUT_MS also sets page.evaluate and render timeouts
ci: longer CDP answer timeout on shared runners (AGENT3D_CDP_TIMEOUT_MS)
fix(assets): assets list is read-only (reports stale sizes instead of rewriting the manifest)
templates: banner-neon-title — readable hot-pink letters (deep base colour + neon emissive, night IBL, bloom threshold 0.9), self-lit sun
runtime HUD: 3x3 grid layout (no overlapping anchors, centre column capped / spanning)
library: CC0 bakery models (croissant, baguette, …) generated by scripts/make-bakery-models.mjs
examples: show the prompt under each template, add the blind-QA client briefs page
hermes: regenerate skills
```

Large waves (`v0.2 wave: …`, `0.2.0 polish: …`) were maintainer commits; a PR
stays focused on one change.

Never add a `Co-Authored-By: Claude` or "Generated with Claude Code" line.

## Scope

Lower case, naming what a user or contributor recognises:

| Scope | What |
|---|---|
| `runtime`, `runtime <area>` (`runtime HUD`, `runtime ground`), `postfx`, `physics`, `element` | `src/runtime/` |
| `generators`, `shaders`, `audio`, `fonts` | procedural content |
| `scene`, `check`, `export`, `assets`, `optimize`, `catalog` | `src/core/`, `src/ops/` |
| `ai`, `mcp` | `src/ai/`, `agent/mcp/` |
| `cli`, `render`, `serve` | `agent/` |
| `studio` | `src/studio/` |
| `templates`, `template <id>`, `library`, `examples` | content |
| `skills`, `hermes`, `docs`, `docs(readme)`, `ci`, `package` | distribution |

A feature spanning engine + CLI + docs + skills takes the scope of what the user
sees. Unrelated changes are separate commits. Release commits (the bare version
`0.2.1` written by `npm version`, `changelog: x.y.z`) belong to the maintainer.

## Subject

- What changed, from the user's point of view, present tense, no trailing period.
  A parenthesis or a dash may add the reason or the details.
- Aim for ≤ 72 characters; never more than ~120.
- Lower case after the colon, except names, commands, identifiers and acronyms.

## Body

Optional; plain prose wrapped at ~80 characters, the problem before the fix,
user-visible effects, new options / scene fields, what a reviewer must test.
`Closes #N` / `Refs #N` at the end.

## Branch names

`<type>/<3-5-word-kebab-summary>` (e.g. `fix/render-cdp-timeout`). Agent worktrees
create `worktree-agent-<id>` branches: rename them before pushing a PR.

## What to avoid

- Generic subjects: "fix bug", "update files", "wip".
- Describing the request ("as asked…") instead of the change.
- Mixing an unrelated fix into a feature commit.
